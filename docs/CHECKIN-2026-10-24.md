# Allowance: two-minute demo (October 24, 2026)

The [check-in page](CHECKIN.md) has the links, the deployment and the progress. This page is a walkthrough anyone can repeat in two minutes, without a wallet, plus screenshots of each step.

## 30-second pitch

> AI agents need to pay for data and compute, but giving them a wallet makes one bad instruction expensive. Allowance puts enforceable spending rules on Portaldot V3. Owners set budgets, caps, trusted recipients and expiry. Agents pay on their own within those rules; payments outside them wait for the owner, and a frozen or expired agent cannot pay at all. The owner keeps control without signing every routine payment.

## Two-minute demo

Open https://oziman13.github.io/allowance/ in a fresh browser window, no wallet needed. The amounts below come from the interactive demo, which runs the real contract bytecode in your browser.

| Time | Do | What it shows |
|---|---|---|
| 0:00 | On the landing page, switch between **Autonomous payment**, **Owner approval** and **Policy block**. | The three outcomes of a payment: paid at once, waiting for the owner, blocked. |
| 0:12 | Press **Try Interactive Demo**. | The contract is deployed into an in-browser chain, with a demo agent that has already spent. |
| 0:25 | Look at the agent's control field. | 1 POT per payment, 5 POT a day, trusted recipients only. 4 POT can still be spent today without asking; the account holds 19 POT. Two requests are waiting. |
| 0:40 | In **Test an agent payment**, keep the trusted recipient, amount **0.1**, press **Send as agent**. | Paid at once. Balance 18.9 POT, 3.9 POT left for today. |
| 0:55 | Change the amount to **2.5** and send. | Over the 1 POT cap, so it is held, not paid. Balance and daily allowance don't change. |
| 1:10 | In the approval inbox, approve the new request. | Paid after the owner's approval: balance 16.4 POT. Approved payments don't use up the agent's daily allowance (still 3.9 POT). |
| 1:30 | Set the amount back to **0.1** and press **Freeze agent**. | The field turns red and the payment button is disabled: the agent can't pay, refuel gas or ask. |
| 1:45 | Press **Unfreeze**. | The agent is back under exactly the same rules. |

To start over, press **Leave simulation** and **Try Interactive Demo** again: the demo starts from the same state every time.

## The same flow on the real testnet

On October 23 a real AI assistant ran this flow on the Portaldot V3 testnet: Claude, through the Allowance MCP server, paid 0.3 POT at once (block [159822](https://scanner-testnet-v3.portaldot.dev/#/blocks/159822)), asked for 2 POT and was held (block [160197](https://scanner-testnet-v3.portaldot.dev/#/blocks/160197)), was approved by the owner (block [160213](https://scanner-testnet-v3.portaldot.dev/#/blocks/160213)), and refused to pay after the owner froze the agent (block [160231](https://scanner-testnet-v3.portaldot.dev/#/blocks/160231)). ## Run the checks yourself

```sh
forge build && forge test            # 27 contract tests, incl. a 1,000-run fuzz test
(cd mcp && npm install && npm test)  # 6 end-to-end MCP tests
python3 build.py                     # builds docs/index.html from web/
python3 script/check_submission.py   # repository, on-chain and submission checks (read-only)
```

The browser test scripts (`script/ui-smoke.cjs`, `script/policy-field-smoke.cjs`, `script/checkin-smoke.cjs`) run the interactive demo in Playwright at several screen sizes; `script/wallet-smoke.cjs` covers the wallet paths: no wallet on a laptop or a phone, several wallets, reconnecting, and a wallet on another network. They need Playwright and Chromium; see the comments at the top of each script. Notes from the October 23 redesign: [UI-PHASE1.md](UI-PHASE1.md), [UI-PHASE2.md](UI-PHASE2.md).
