Allowance
Not connected

Give your AI agent an allowance, not a wallet.

Your agent spends from a budget with rules that live on Portaldot. Small payments go through on their own. Anything bigger, or to someone new, waits for you.

The simulation runs the real contract in your browser, with a demo agent already spending. No wallet, no test tokens.

How it works

  1. Set the rules. Open an allowance for an agent key: a budget, a cap per payment, a cap per day or week, and who it may pay without asking.
  2. The agent pays. Inside the rules, payments settle at once, gas included. The contract checks every payment, so the agent can't skip the check.
  3. You decide the rest. Anything outside the rules waits with the agent's reason. Approve it, trust the recipient for next time, or reject it. Freeze the agent with one click.

If your agent is wrong, jailbroken or prompt-injected

A wallet keySpend everything in the wallet.
A proxy accountAct for you. Proxies limit which calls, not how much.
A confirm button in an appSkip it. The check lives in the app, not on chain.
An allowanceSpend within your caps, to recipients you trust. Everything else waits for you, enforced by the contract.

Made for Portaldot V3

Gas comes from the same budget. Gas on Portaldot is POT, so the agent refuels from its allowance, under the same caps. Five POT a day means five POT a day.

Cheap where it matters. V3 charges for new storage, so instant payments only update what's there: 0.03 POT each, measured on chain.

Works with AI assistants. An MCP server gives Claude, Cursor or any MCP client five tools: check, preview, pay, request, cancel. It holds only the agent key.
